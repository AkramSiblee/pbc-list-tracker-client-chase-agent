# PBC List Tracker & Client Chase Agent

Generates a PBC (Prepared By Client) list from one or more audit programs,
tracks receipt across a multi-entity Drive/inbox structure, drafts chase
emails, and maintains a live dashboard — built to hold up under real Big
4-caliber group-audit complexity: multiple components, confidentiality tiers,
GDPR/data-residency rules, materiality-weighted urgency, dependency chains,
client disputes, interim-to-final rollforward, and PBC items generated
dynamically from fieldwork sampling (not just the static audit program).

## Setup

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

You also need `pandoc` on PATH (used to parse the `.docx` audit programs):

```bash
# macOS
brew install pandoc
# Debian/Ubuntu
sudo apt-get install pandoc
```

## Running it

```bash
# Generate config from the engagement setup workbook (run once, and again
# whenever that workbook changes):
python scripts/generate_config.py

# Core pipeline:
python scripts/extract_pbc_items.py       # parses the 4 sample audit programs
python scripts/build_master_tracker.py    # assembles the local tracker mirror
python scripts/match_submissions.py       # classifies the 19-row test harness

# Run the test suite:
python -m pytest tests/ -v
```

## What's real vs. what's a placeholder

Everything in `scripts/` actually runs against the real sample data and is
covered by tests — this isn't a mockup. What's **not** wired up yet is live
Gmail/Drive access: this was originally scoped for Claude Cowork's built-in
connectors, and moving it into Claude Code/VS Code means deciding between
MCP-server access (if configured for this environment) or a direct Google API
/ OAuth integration. See `CLAUDE.md`'s "Integration decision not yet made"
section before wiring that up — the scripts here are connector-agnostic and
don't need to change either way.

## Sample scenario

The sample data models a group audit of **Meridian Global Holdings Inc.**
(US parent) with three existing components — Meridian Europe GmbH (Germany,
component auditor), Meridian Asia Pacific Pte Ltd (Singapore, group-audited
directly), Meridian Manufacturing Co. (Canada, insignificant but flagged for
related-party risk) — plus **Meridian Nordics AB**, a mid-year acquisition
scoped for opening-balance-sheet and purchase-price-allocation procedures
only. Every rule in the two spec docs has at least one corresponding test
case in `sample_data/test_harness/Drive_Inbox_Submission_Log.xlsx`.
